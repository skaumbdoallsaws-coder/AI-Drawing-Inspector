### Citation defect probe and customer-copy policy

Claude's real MMLE run found that the compiled rows have only `cells`, with no
row claimIds/sourceIds. Page `page-specifications-1`, block `spec-table-1`, row 0
is `["Rated capacity", "1,100 lb"]`; the block carries `evidenceClaimIds`, including
CLM-SPEC-001, while the document carries `evidenceCitations`. The old probe's
three-cell/per-row-claim search therefore failed with StopIteration. The raw plan
rows in `document.py::_specification_rows` do carry claimIds/sourceIds, but
`content.py::prototype_sections` supplies unannotated specification cells to the
publication table. `flow.py::_place_table` preserves keys supplied to it; it
cannot recover that absent relation. The synthetic annotated-table probe does
not establish the real compiled row shape.

The corrected probe submits `update_text` for `spec-table-1.r0.c1`, changing
"1,100 lb" to "1,000 lb", then rereads the compiled document and applies the
exporter's `_edited_block` adapter. It records the retained block claim and linked
source authorities. It requires the complete edited capacity row to appear in
both PDF and DOCX text, not just the number somewhere else in the document.

Source tracing shows neither operations exporter reads `evidenceCitations` or
`authority` to print an inline badge on the specification row. Both draw layout
blocks and their effective cells. `content.py::_source_rows` maps OEM_CURRENT to
"Current manufacturer source" in the separate source register's "Evidence role
and limitations" cell, followed by the claim count and any limitations. The probe
matches that register row by the linked citation's title and records its exact
cells plus its presence in extracted PDF/DOCX text. It does not label the capacity
cell itself "OEM current" or equate a register label with a per-value citation.
