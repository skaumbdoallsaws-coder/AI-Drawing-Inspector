## P2b-1

### CHANGED

- **ai_inspector/documentation/rich_layout.py**: added a schema-1 content model, bounded paragraph/run layout using real built-in font metrics, and shared PDF preflight/drawing. It handles marks, H1-H3, hard breaks, numbered/bulleted lists to three levels, hanging indents, whitespace, per-run underlines, exact URI annotations, and existing object fill/outline/opacity rules. Layout reports positioned lines/runs, measured height, overflow, and unsupported code points. It reads canonical composition content, never a rich field's display projection.
- **ai_inspector/parts_manual/pdf.py**: rich objects use the shared path; the legacy plain text drawing block is unchanged. **ai_inspector/specification_sheet/exports.py** and **ai_inspector/operations_manual/exports.py** now draw all authored text objects, including plain strings. This covers specification PDF/fillable PDF and WI's delegated PDF builder. Operations invalidates old cached PDFs containing text objects with a renderer-version marker; caches without text objects retain their existing contract.
- **ai_inspector/documentation/rich_text.py**, **provenance.py**, and the DOCX entry points in specification, operations, and **ai_inspector/work_instructions/exports.py**: PDF passes the rich-feature guard; DOCX still refuses with unsupported_export_feature, feature=rich_text, format=docx, and target IDs. Existing citation and conflict checks/markers remain in place.
- **server.py**: specification, operations, and WI PDF routes also request a companion DOCX. They now return the successful PDF with an explicit unsupported DOCX descriptor (no URL) when rich text is present. Otherwise the existing paired export behavior is unchanged. This prevents a deferred DOCX from making a completed PDF request fail.
- **tests/test_documentation_rich_exports.py**: added real PDF extraction tests for font variants/flags/colors, underlines, links, headings/lists, whitespace, NFC/CJK, frames, wrapping, glyph/overflow/rotation refusals, artifact writes, all five PDF paths in all four modes, cache invalidation, legacy equality, and combined HTTP responses. **tests/test_documentation_rich_text.py**: replaced the superseded blanket PDF-refusal expectations with DOCX-only refusals; PDF coverage is in the new file.

Rendering uses only PyMuPDF built-in font programs: the existing base14 family/variant mapping, with the built-in CJK fallback after a real glyph check. Fonts are embedded from those in-memory programs; no font files or system font paths are used. Tabs advance four spaces in the run's font, not to a tab stop. Literal CR advances one space, matching the P2a supervisor gate; LF/hardBreak ends a line. NFC applies only to rendering, across adjacent identically styled text. The stored content is unchanged. H1/H2/H3 size multipliers are 1.75/1.5/1.25.

Unsupported glyphs refuse with unsupported_export_glyph and target/code-point details. Insufficient frame space refuses with layout_overflow before artifact writing; there is no shrink-to-fit or clipping on the new path.

**Baseline expectation: neither moves for the supplied worktree inputs.** The saved generated/parts_manual/mmle-50d/documentation-scene.json contains zero text objects. The worktree has no generated/specification_sheets, generated/operations_manual, or generated/work_instructions store directories. No external/live stores were inspected. Specification/operations/WI documents that do contain text objects will intentionally change because those objects were previously omitted. Parts plain-object output stays unchanged.

**P2b-2 content model handoff:** use authored_objects(page) to obtain (target ID, object, canonical value), resolve the existing object base style, then call content_model(value, style). It does not import PyMuPDF or contain PDF positions.

- Content: paragraphs, base_size, base_run.
- Paragraph: kind (paragraph/heading), heading_level, font_family, resolved font_size, align, list_path, marker, runs.
- ListLevel in list_path: list_id, kind (bulletList/orderedList), start, ordinal. IDs are deterministic and local to one field; namespace them by target when creating DOCX numbering. A continuation paragraph retains its list path but has marker=None; each new list gets a separate identity/counter.
- Run: kind (text/break), raw text, bold, italic, underline, color, href. Base object styling is already combined with marks. A break is a native line break; preserve raw spaces, tabs, CR and Unicode when consuming text. Plain conversion is one paragraph with LF hard breaks, matching from_plain. No authored IDs are saved or regenerated by export.
- DOCX must consume this content model, not Layout/Line/PositionedRun or PDF-normalized text. Native DOCX writing and the P2b smoke remain P2b-2 work.

### Supervisor fixes (Claude)

The PDF layout now mirrors the canvas box (documentation_rich_text.js render() inside .documentation-object.text), where one page px is one PDF point:
- Lines are LINE_HEIGHT (1.2) x the size, with the CSS half-leading baseline.
- PADDING (3) sits inside the outline width (border-box), and the border stroke is drawn inside the box.
- Headings are bold at 2.0, 1.5 and 1.17x the base size.
- Links are underlined and #0000ee unless explicitly colored. The canvas nests the color span inside the link, so an explicit color wins.
- Lists indent 40 pt per level. Outside markers (a bullet or "7.", plus a space) end at the item text.
- Bullets go disc, circle, square by nesting depth. Circle and square come from the built-in CJK font, with a fall back to disc if it lacks them.
- White space follows pre-wrap. Only U+0020 breaks and hangs at a line end; tabs and CR are drawn as spaces. Hanging spaces do not count toward fit or alignment, and carry no underline or link.
- A final hard break or LF adds no empty line, as the canvas renders <p>a<br></p>.
- Line breaking uses a small UAX #14 subset:
  - breaks between ideographs, kana and Hangul syllables;
  - never before closing punctuation, small kana or iteration marks;
  - never after opening punctuation;
  - a no-break space binds.
- Lines measure advances, not ink. PyMuPDF's glyph_bbox returns the whole font box for the built-in CJK font (-0.56 to 1.12 em), which widened every ideograph by 12%.

Checked against Chromium (scratch script canvas_vs_pdf.py). It lays out 11 samples in headless Chromium with the canvas CSS and the static renderer's DOM, then compares line texts and content height with layout_text. The samples:
- marks, heading and nested lists;
- a long wrap at 12 pt;
- H1-H3;
- bold centered text;
- hanging spaces;
- Times at 14 pt;
- an overlong word;
- CJK mixed with Latin;
- CJK closing punctuation;
- a no-break space;
- Korean.

All 11 break into identical lines. Content heights agree within 0.13 pt, which is Chromium's 1/64 px layout rounding. So the PDF's overflow decision now matches what the user sees.

Fonts:
- Any glyph of the object's built-in family is used, since fonts are embedded as Unicode CID fonts. Codex limited the base family to WinAnsi, which sent a-macron, l-stroke and similar letters to the CJK font.
- The CJK fallback has no bold or italic face. Both are now synthesized as browsers do (fill plus a 0.04 em stroke; a 14 degree shear) instead of refused.
- finish_pdf_fonts subsets embedded fonts before saving. It runs only when this path drew something, so every other export keeps its bytes.
  - CJK spec sheet: 1.84 MB -> 69.5 KB. Latin spec sheet: 132 KB -> 61 KB.
  - Subset tags are content-derived, so bytes still differ only by the random trailer ID.

Smaller:

- refuse_export's format is now a required keyword. An exporter that forgets it fails instead of skipping the DOCX refusal.
